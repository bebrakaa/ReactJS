# Лабораторная работа №3 - Интернет-магазин с Redux

Три реализации одного и того же интернет-магазина с использованием разных подходов к управлению состоянием.

## 📋 Задание

Создать веб-приложение — прототип интернет-магазина, включающего в себя следующие страницы:

1. Список товаров, которые загружаются с сервера
2. Корзина, содержащая список товаров для покупки и кнопку оформления заказа
3. Страница оформления заказа в несколько стадий (симуляция оплаты)
4. Страница для отображения списка созданных заказов
5. Страницы регистрации и авторизации пользователей

Разработать веб-приложение необходимо **три раза** с использованием трех различных подходов:

1. ✅ С использованием библиотек **redux** и **redux-thunk**
2. ✅ С использованием библиотеки **@reduxjs/toolkit** (с применением slice)
3. ✅ С использованием библиотек **@reduxjs/toolkit** и **@reduxjs/toolkit/query/react**

## 📊 Сравнение подходов

| Характеристика | Redux + Thunk | Redux Toolkit | RTK Query |
|----------------|---------------|---------------|-----------|
| **Boilerplate** | Много | Средне | Минимум |
| **Сложность** | Средняя | Низкая | Низкая |
| **Гибкость** | Высокая | Высокая | Средняя |
| **Кеширование** | Ручное | Ручное | Автоматическое |
| **DevTools** | Да | Да | Да + Network |
| **Типизация** | Ручная | Автоматическая | Автоматическая |

### Вариант 1: Redux + Redux-Thunk (Классический подход)

**Преимущества:**
- ✅ Полный контроль над логикой
- ✅ Прозрачность работы
- ✅ Гибкость в реализации

**Недостатки:**
- ❌ Много boilerplate кода
- ❌ Ручное управление типами действий
- ❌ Повторяющийся код

**Когда использовать:**
- Нужен полный контроль
- Сложная бизнес-логика
- Обучение основам Redux

### Вариант 2: Redux Toolkit (Современный подход)

**Преимущества:**
- ✅ Меньше boilerplate
- ✅ Встроенные best practices
- ✅ Автоматическая типизация
- ✅ Immer для иммутабельности

**Недостатки:**
- ❌ Нужно изучить новый API
- ❌ Меньше гибкости

**Когда использовать:**
- Новые проекты
- Стандартные CRUD операции
- Нужна производительность

### Вариант 3: RTK Query (Подход с кешированием)

**Преимущества:**
- ✅ Автоматическое кеширование
- ✅ Минимум кода
- ✅ Автоматическая синхронизация
- ✅ Оптимистичные обновления

**Недостатки:**
- ❌ Меньше контроля
- ❌ Сложнее кастомизация

**Когда использовать:**
- API-driven приложения
- Нужно кеширование
- Минимум кода

## 📡 API Endpoints

### Авторизация:
- `POST /api/login` - вход
- `POST /api/register` - регистрация
- `GET /api/me` - текущий пользователь

### Товары:
- `GET /api/products` - список товаров (с фильтрами)
- `GET /api/categories` - список категорий

### Заказы:
- `GET /api/orders` - список заказов пользователя
- `POST /api/orders` - создание заказа
- `PATCH /api/orders/:id/cancel` - отмена заказа
