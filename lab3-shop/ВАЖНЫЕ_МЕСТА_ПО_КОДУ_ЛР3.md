# Важные места по коду ЛР3

Этот файл нужен как короткая шпаргалка: где в проекте смотреть реализацию основных пунктов задания и что именно там происходит.

## Общая логика проекта

`server/server.js`

Общий сервер для всех трех вариантов. Здесь находятся API-маршруты для регистрации, входа, проверки пользователя, загрузки товаров, категорий, создания заказов, просмотра истории заказов и отмены заказа.

`server/db.json`

Файл с данными приложения: пользователи, товары, категории и заказы.

`variant*/src/config/api.js`

Общие настройки клиента: адрес API и количество товаров на странице. Это вынесено отдельно, чтобы не писать `http://localhost:5000/api` в разных файлах вручную.

`variant*/src/index.js`

Точка входа приложения. Здесь подключается Redux `Provider`, роутинг, `AppInitializer`, а также описаны маршруты страниц. Важный момент: защищенные страницы находятся внутри `ProtectedRoute`.

`variant*/src/App.js`

Общий layout приложения. Здесь находится общий каркас страниц: `Header` и `Outlet`, куда React Router подставляет текущую страницу.

`variant*/src/components/ProtectedRoute.js`

Проверяет, авторизован ли пользователь. Если пользователь не вошел в систему, защищенные страницы не открываются.

## Страницы по заданию

### 1. Список товаров, которые загружаются с сервера

`variant*/src/pages/ProductsPage.js`

Главная страница каталога. Здесь отображаются товары, фильтры, поиск, категории, пагинация и кнопки добавления в корзину.

`variant*/src/components/ProductCard.js`

Карточка одного товара. Показывает название, цену, описание и кнопку добавления товара в корзину.

`variant*/src/hooks/useProducts.js`

Кастомный хук для работы с товарами. Он помогает странице товаров не разрастаться: часть логики загрузки, фильтров и пагинации вынесена сюда.

### 2. Корзина товаров

`variant*/src/pages/CartPage.js`

Страница корзины. Здесь выводится список выбранных товаров, итоговая сумма и кнопка перехода к оформлению заказа.

`variant*/src/components/CartItem.js`

Одна позиция в корзине. Здесь можно увеличить или уменьшить количество товара, ввести количество вручную, удалить товар из корзины.

`variant*/src/redux/*/cart*`

Redux-логика корзины. В зависимости от варианта файл находится в разных местах:

`variant1-redux-thunk/src/redux/reducers/cartReducer.js`

`variant1-redux-thunk/src/redux/actions/cartActions.js`

`variant2-redux-toolkit/src/redux/slices/cartSlice.js`

`variant3-rtk-query/src/redux/slices/cartSlice.js`

### 3. Оформление заказа в несколько стадий

`variant*/src/pages/CheckoutPage.js`

Страница оформления заказа. Здесь реализованы этапы: данные покупателя, адрес доставки, способ оплаты и подтверждение заказа.

`variant*/src/utils/validation.js`

Функции валидации форм. Сюда вынесены проверки полей, чтобы не держать всю логику прямо внутри страниц.

### 4. Список созданных заказов

`variant*/src/pages/OrdersPage.js`

Страница истории заказов. Здесь загружаются заказы пользователя, есть фильтр по статусу и вывод списка заказов.

`variant*/src/components/OrderCard.js`

Карточка одного заказа. Показывает номер, дату, статус, сумму, детали заказа. Карточку можно раскрывать и скрывать.

`variant*/src/redux/*/orders*`

Redux-логика заказов. В зависимости от подхода находится здесь:

`variant1-redux-thunk/src/redux/actions/ordersActions.js`

`variant1-redux-thunk/src/redux/reducers/ordersReducer.js`

`variant2-redux-toolkit/src/redux/slices/ordersSlice.js`

`variant3-rtk-query/src/redux/api/ordersApi.js`

### 5. Регистрация и авторизация пользователей

`variant*/src/pages/LoginPage.js`

Страница входа. Пользователь вводит email и пароль, после успешного входа сохраняется токен.

`variant*/src/pages/RegisterPage.js`

## Вариант 1: Redux + redux-thunk

Папка: `variant1-redux-thunk`

Главная идея: классический Redux, где отдельно лежат типы действий, actions и reducers.

Важные файлы:

`src/redux/actionTypes.js`

Здесь описаны константы действий, например загрузка товаров, успешная загрузка, ошибка загрузки.

`src/redux/actions/productsActions.js`

Здесь находятся thunk-функции для товаров. Они делают запрос на сервер и отправляют actions в Redux.

`src/redux/actions/authActions.js`

Логика входа, регистрации, выхода и проверки пользователя.

`src/redux/actions/ordersActions.js`

Создание заказа, загрузка заказов и отмена заказа.

`src/redux/reducers/*.js`

Reducers обновляют состояние после actions. Например, при успешной загрузке товаров записывают товары в `state.items`.

`src/redux/store.js`

Создает Redux store и подключает `thunk` middleware.

Особенность подхода: он самый подробный. Хорошо видно, как работает Redux, но кода больше всего.

## Вариант 2: Redux Toolkit + slice

Папка: `variant2-redux-toolkit`

Главная идея: Redux Toolkit уменьшает количество шаблонного кода. Логика каждой сущности находится в своем `slice`.

Важные файлы:

`src/redux/slices/authSlice.js`

Slice для авторизации: вход, регистрация, проверка токена, выход.

`src/redux/slices/productsSlice.js`

Slice для товаров: загрузка товаров, категории, фильтры, пагинация.

`src/redux/slices/cartSlice.js`

Slice для корзины: добавление, удаление, изменение количества, очистка корзины.

`src/redux/slices/ordersSlice.js`

Slice для заказов: создание заказа, загрузка истории, отмена заказа.

`src/redux/store.js`

Создает store через `configureStore`. Redux Toolkit сам удобно настраивает Redux, поэтому кода меньше.

Особенность подхода: это самый сбалансированный вариант. Код чище, чем в классическом Redux, но логика все еще хорошо читается.

## Вариант 3: Redux Toolkit Query

Папка: `variant3-rtk-query`

Главная идея: RTK Query берет на себя работу с серверными запросами. Мы описываем API, а библиотека сама создает хуки для React.

Важные файлы:

`src/redux/api/apiSlice.js`

Базовый API slice. Здесь задается общий адрес сервера и подготовка заголовков, например добавление токена авторизации.

`src/redux/api/authApi.js`

Endpoints для входа и регистрации.

`src/redux/api/productsApi.js`

Endpoints для загрузки товаров и категорий.

`src/redux/api/ordersApi.js`

Endpoints для создания, загрузки и отмены заказов.

`src/redux/slices/cartSlice.js`

Корзина остается обычным slice, потому что она в основном хранит локальное состояние.

`src/redux/slices/authSlice.js`

Локальное состояние авторизации: текущий пользователь, токен, состояние входа.

`src/redux/slices/filtersSlice.js`

Локальные фильтры каталога.

`src/redux/store.js`

Подключает `apiSlice.reducer` и `apiSlice.middleware`. Это нужно, чтобы RTK Query мог кэшировать данные и управлять запросами.

Особенность подхода: меньше всего ручного кода для запросов к серверу. Хорошо подходит, когда приложение много работает с API.

## Как быстро объяснить преподавателю разницу

Redux + thunk: все делается вручную. Есть actions, reducers, action types и thunk-функции для запросов.

Redux Toolkit: тот же Redux, но компактнее. Логика одной сущности лежит в `slice`, а асинхронность чаще делается через `createAsyncThunk`.

RTK Query: подход для работы с API. Мы описываем endpoints, а RTK Query сам создает хуки, хранит загрузку, ошибки и кэш.

## Что важно сказать про архитектуру

Роутинг вынесен в `index.js`, потому что это точка входа приложения.

`App.js` отвечает только за общий layout и не хранит бизнес-логику.

Страницы лежат в `pages`, потому что это полноценные экраны приложения.

Переиспользуемые элементы лежат в `components`.

Redux-логика лежит в `redux`, отдельно для каждого подхода.

Повторяемая логика авторизации и товаров вынесена в `hooks`.

Валидация вынесена в `utils/validation.js`, чтобы не смешивать проверки форм с JSX-разметкой страниц.

Настройки API вынесены в `config/api.js`, чтобы не дублировать адрес сервера.
