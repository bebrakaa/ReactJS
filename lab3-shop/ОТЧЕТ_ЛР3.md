## ЦЕЛЬ РАБОТЫ:

Изучить и сравнить три подхода к управлению состоянием в React-приложениях с использованием библиотеки Redux: классический Redux с middleware redux-thunk, современный Redux Toolkit с применением slice-редьюсеров и Redux Toolkit с RTK Query для работы с API.

## ЗАДАНИЕ:

Создать веб-приложение — прототип интернет-магазина, включающего в себя следующие страницы:

1) список товаров, которые загружаются с сервера;
2) корзина, содержащая список товаров, которые пользователь желает купить и кнопку для оформления заказа;
3) страница оформления заказа в несколько стадий (симуляция оплаты);
4) страница для отображения списка созданных заказов;
5) страницы регистрации и авторизации пользователей.

Разработать веб-приложение необходимо три раза с использованием трех различных подходов:

1) С использованием библиотек redux и redux-thunk
2) С использованием библиотеки @reduxjs/toolkit (с применением slice)
3) С использованием библиотек @reduxjs/toolkit и @reduxjs/toolkit/query/react

### 2) Отличия трех подходов:

| Характеристика | Подход 1: Redux + Thunk | Подход 2: Redux Toolkit (Slice) | Подход 3: RTK Query |
|----------------|-------------------------|----------------------------------|---------------------|
| **Код** | Много шаблонного кода (actions, reducers отдельно) | Меньше кода, все в одном файле (slice) | Минимум кода, автоматическая генерация хуков |
| **Бойлерплейт** | Много (нужно писать action types, actions, reducers) | Средне (только slice) | Минимум (только API definition) |
| **Асинхронность** | Вручную через thunk middleware | Встроенный `createAsyncThunk` | Автоматическая с `useQuery`/`useMutation` |
| **Кэширование** | Нужно реализовывать вручную | Нужно реализовывать вручную | Встроенное автоматическое |
| **Обновление данных** | Ручное | Ручное | Автоматическое (polling, refetch) |
| **Иммутабельность** | Вручную (spread operators) | Автоматическая (Immer) | Автоматическая (Immer) |
| **Сложность изучения** | Высокая | Средняя | Низкая |
| **Рекомендация Redux** | Устаревший | Актуальный | Актуальный для API |
| **Размер кода** | ~500 строк | ~300 строк | ~200 строк |

### 3) Ключевые особенности реализации:

#### **Variant 1 - Redux + Redux-Thunk:**

**Структура действий:**
```javascript
// actions/productsActions.js
export const fetchProducts = (filters) => {
  return async (dispatch) => {
    dispatch({ type: FETCH_PRODUCTS_REQUEST });
    try {
      const response = await fetch(`/api/products?...`);
      const data = await response.json();
      dispatch({ type: FETCH_PRODUCTS_SUCCESS, payload: data });
    } catch (error) {
      dispatch({ type: FETCH_PRODUCTS_FAILURE, payload: error.message });
    }
  };
};
```

**Особенности:**
- Отдельные файлы для actions и reducers
- Ручное управление состоянием загрузки
- Много повторяющегося кода

---

#### **Variant 2 - Redux Toolkit (Slice):**

**Структура slice:**
```javascript
// slices/productsSlice.js
const productsSlice = createSlice({
  name: 'products',
  initialState: { items: [], loading: false, error: null },
  reducers: {
    setFilter: (state, action) => {
      state.filters[action.payload.filterName] = action.payload.value;
    },
  },
  extraReducers: (builder) => {
    builder
      .addCase(fetchProducts.pending, (state) => {
        state.loading = true;
      })
      .addCase(fetchProducts.fulfilled, (state, action) => {
        state.items = action.payload;
        state.loading = false;
      });
  },
});
```

**Особенности:**
- Все в одном файле (actions + reducers)
- Автоматическое создание action creators
- Можно "мутировать" state (благодаря Immer)
- Меньше кода

---

#### **Variant 3 - RTK Query:**

**Структура API:**
```javascript
// api/productsApi.js
export const productsApi = apiSlice.injectEndpoints({
  endpoints: (builder) => ({
    getProducts: builder.query({
      query: (filters) => `/products?${params}`,
    }),
  }),
});

export const { useGetProductsQuery } = productsApi;
```

**Использование в компоненте:**
```javascript
const { data: products, isLoading, error } = useGetProductsQuery(filters);
```

**Особенности:**
- Автоматическая генерация хуков
- Встроенное кэширование
- Автоматическое управление состоянием загрузки
- Минимум кода

## ВЫВОДЫ:

В ходе выполнения лабораторной работы я успешно изучил и сравнил три подхода к управлению состоянием в React-приложениях с использованием библиотеки Redux:

1. **Redux + Redux-Thunk** - классический подход с большим количеством шаблонного кода, но полным контролем над логикой.

2. **Redux Toolkit (Slice)** - современный подход, значительно сокращающий количество кода и упрощающий разработку благодаря `createSlice` и встроенному Immer.

3. **RTK Query** - наиболее современный подход для работы с API, предоставляющий автоматическое кэширование, управление состоянием загрузки и минимальное количество кода.

**Рекомендации:**
- Для новых проектов рекомендуется использовать **Redux Toolkit** или **RTK Query**
- **RTK Query** идеален для приложений с активной работой с API
- Классический Redux + Thunk следует использовать только для поддержки legacy кода

Все три варианта приложения полностью функциональны и демонстрируют одинаковый пользовательский опыт, различаясь только внутренней реализацией управления состоянием.
